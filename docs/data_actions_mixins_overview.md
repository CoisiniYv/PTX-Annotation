# data_mixin.py 与 actions_mixin.py 总览

## 模块定位

- `data_mixin.py`：数据侧「发动机」。负责**扫描目录、组织病例列表、加载/缓存影像与掩码、预取与缩略图生成，以及标注状态/标签的持久化**。
- `actions_mixin.py`：交互侧「控制台」。负责**响应用户操作（拖拽、快捷键、菜单）、驱动保存/加载/导出流程，以及触发 UI 状态更新和性能设置**。

两者组合后，主窗口类只需要关注「界面布局和业务流程」，具体的数据调度与交互细节由这两个 Mixin 提供。

---

## data_mixin.py 主要职责

1. **病例扫描与分类（列表数据源）**
   - 根据当前扫描模式（CT / X 光）遍历原图目录：
     - CT：一级子目录作为一个病例（一个序列）。
     - X 光：每个图像文件作为一个病例。
   - 对比掩码目录和 `case_status.json`：将病例划分到「已标注 / 待标注」列表，并通过 UI 列表展示。

2. **标注标签与完成状态持久化**
   - `pneumothorax_labels.json`：记录病例的气胸标签（阳性 / 阴性）。
   - `case_status.json`：记录病例是否完成标注。
   - 支持任务 JSON 模式（Task Mode）：
     - 通过外部任务 JSON 限定工作集。
     - 状态文件名自动跟随任务 JSON（`<task_name>_case_status.json`）。
   - 内部维护 `_labels_cache` + 定时器：
     - 标记为 dirty 后延迟写盘，降低频繁 I/O。

3. **图像与掩码的缓存 / 内存池管理**
   - `_image_cache`：
     - LRU 策略，按访问顺序维护；超过 `ct_cache_max / xray_cache_max` 时自动淘汰最久未使用的条目。
     - 缓存内容通常为 `(img, mask, meta)`。
   - `_mask_pool`：
     - 可选的掩码内存池，按最大高宽预分配 numpy 数组，重复复用，减少频繁的 `np.zeros` 分配和 GC 压力。

4. **多线程预取（Prefetching）**
   - 序列内预取：当前看第 N 张时，后台加载 N±1 等附近切片，减缓翻页时的顿挫感。
   - 跨病例预取：提前加载下一病例的首张图像及掩码，使病例切换接近「秒切」。
   - 使用 `epoch` / `token` 机制管理预取任务：
     - 每次切换病例/位置都会提升 epoch，旧任务检测到 epoch 变化后自动退出，避免将旧数据写入当前状态。

5. **缩略图生成与 UI 解耦**
   - CT 模式下：
     - 后台线程遍历一个序列所有切片，生成缩略图并压入队列。
     - 前台使用定时器批量拉取缩略图并刷新 UI 列表，避免主线程卡死。

## actions_mixin.py 主要职责

1. **文件拖拽与加载流程**
   - `_connect_canvas_signals()`：
     - 在主窗口初始化时连接 canvas 的 `file_dropped` 信号到 `_on_mask_file_dropped`。
   - `_on_mask_file_dropped(path)`：
     - 接收用户拖拽的掩码文件（`.png` / `.nii` / `.nii.gz`）。
     - 调用 `read_mask_file()`，按当前图像尺寸重采样或对齐。
     - 更新画布掩码、撤销栈状态以及 `entry.has_mask` / `entry.mask_path`。
     - 记录是否来自 NIfTI，以便保存时保持同格式与空间信息。

2. **掩码保存与清理策略**
   - `save_mask()`：
     - 将当前画布掩码转换为二值图像，按原始掩码格式或用户设置写入（位图 / NIfTI）。
     - 如果是已有 NIfTI，则尽量继承原文件的空间元数据（方向、spacing 等）。
     - 综合考虑自动保存开关、单病例模式、任务模式等状态。
   - `_cleanup_empty_masks()`：
     - 在切换病例或关闭程序时，扫描并删除「全黑掩码文件」，防止磁盘堆积无效文件。

3. **病例标签和 UI 状态更新**
   - `_update_pneumo_label(val)`：
     - 响应快捷键（T/F），更新当前病例的阳性/阴性标签。
     - 写入 labels 缓存，并刷新左侧列表、CT 缩略图边框颜色等视觉提示。
   - `_update_status_ui()`：
     - 将当前文件名、目录、保存状态、气胸标签等信息同步到底部状态栏。

4. **导航与浏览控制**
   - `prev_image()/next_image()`：
     - 在一个序列内按索引前后跳转，触发对应的加载与预取逻辑。
   - `prev_case()/next_case()`：
     - 在病例列表中切换上下病例，并更新当前 entries / 预取 / UI 高亮。

5. **导出与性能设置**
   - `export_current()`：
     - 弹出导出对话框，支持：
       - 指定导出分辨率；
       - 是否反色；
       - 仅图像 / 图像+掩码等选项。
   - `open_perf_settings()`：
     - 打开预取/缓存设置界面，动态调整 `ct_prefetch_count`、`ct_cross_count`、`ct_cache_max`、`xray_prefetch_count`、`xray_cache_max` 以及 X 光默认掩码格式。
     - 同步修改当前 `_image_cache` 大小上限，并触发旧缓存淘汰。

6. **程序关闭时机的收尾处理**
   - `closeEvent()`：
     - 若开启自动保存且当前掩码已修改，则先保存当前掩码。
     - 刷新 labels 缓存，确保 JSON 写盘。
     - 清理空掩码文件，再调用父类 `closeEvent`。

## 协作关系

- `DataMixin` 负责「**准备好数据**」：
  - 把哪些病例、每个病例包含哪些图像、掩码/状态存在哪里、内存里如何缓存，全部组织好。
  - 对上层暴露的是结构化的 `entries` 列表、当前索引、缓存访问接口等。
- `ActionsMixin` 负责「**怎么用数据**」：
  - 收到用户动作（拖拽、快捷键、菜单）后，调用 DataMixin/主窗口暴露的接口，完成加载/保存/跳转。
  - 同时负责把结果反馈到 UI：状态栏、列表、缩略图、画布等。

## 可优化方向建议

### 1. 模块边界与职责收敛

- **问题倾向**：
  - DataMixin 中既有「纯数据逻辑」（扫描、缓存），也夹杂了一些与 UI 相关的定时器和进度对话框操作；
  - ActionsMixin 中部分操作直接访问 DataMixin 的内部细节（如 cache / epoch），存在跨层依赖。
- **优化建议**：
  - 尽量让 DataMixin 只提供「**无 UI 侧效应的服务接口**」，例如：
    - `scan_cases()` / `load_entry()` / `get_cached_image()`；
    - 通过回调/信号把「进度信息」上抛给主窗口或 UI 层，而不是内部直接 new 对话框。
  - ActionsMixin 中只调用这些接口，而不依赖 DataMixin 的私有字段，降低耦合度。

### 2. CT / X 光 分支逻辑统一

- **问题倾向**：
  - 当前很多逻辑以 `if scan_mode == CT_SEQUENCE else ...` 形式散落在各处，例如缓存大小、扫描逻辑、预取策略等。
- **优化建议**：
  - 可以轻量抽象一个「策略类」或「配置表」，将 CT/X 光的差异集中管理：
    - 如 `MODE_CONFIG[ScanMode.CT_SEQUENCE] = {...}`，`MODE_CONFIG[ScanMode.XRAY] = {...}`；
    - DataMixin 依据当前模式从配置中取参数，避免多处硬编码条件判断。
  - 保持简单即可，不必过度抽象。

### 3. 预取与缓存的监控与限流

- **问题倾向**：
  - 预取线程数量、任务排队情况、缓存命中率目前主要靠经验和手感调整；
  - 在极端大数据集或低性能机器上可能出现：
    - 磁盘 I/O 打满；
    - 内存占用抖动较大。
- **优化建议**：
  - 在预取逻辑中增加轻量级统计：当前活跃预取任务数、排队长度、最近一段时间的失败/取消次数等；
  - 允许在 Prefetch 设置页中增加「软上限」，比如：
    - 总预取线程数上限；
    - 当 UI 快速连续切换病例时，对预取任务做更 aggressive 的 cancel。

### 4. JSON 读写与错误处理统一

- **问题倾向**：
  - `pneumothorax_labels.json`、`case_status.json` 的读写逻辑在不同函数中各自处理异常，行为略有差异；
  - 编码容错（`utf-8-sig` / `gbk`）等逻辑散落在 DataMixin 内部。
- **优化建议**：
  - 提炼一个**轻量 JSON 读写助手**（保持在 utils 层，不引入大依赖）：
    - 统一编码探测 / 容错策略；
    - 统一异常打印格式（带上文件路径与简短提示）。
  - DataMixin 只关心业务层面的 dict 结构，不关心底层编码细节。

### 5. 掩码路径与格式决策集中

- **问题倾向**：
  - 掩码路径的确定（默认 PNG、NIfTI、同名搜索等）在多个地方各自推导；
  - 当支持更多格式或存储规则时，改动点较多。
- **优化建议**：
  - 抽一处「掩码定位函数」，输入：
    - 原图路径、当前模式（CT/X 光）、用户默认格式设置；
    - 是否是拖拽覆盖、单对模式等上下文。
  - 输出：具体 mask 保存/读取路径与格式描述；
  - 这样 DataMixin、ActionsMixin 统一通过这层接口处理掩码相关的路径与格式。

### 6. 多线程与 Qt 主线程交互安全

- **问题倾向**：
  - 部分后台线程可能直接操作与 Qt 对象相关的状态或使用非线程安全容器；
  - 现有代码已经通过队列 + 定时器做了一定解耦，但仍需持续留意。
- **优化建议**：
  - 强化约定：
    - 后台线程**只**写入普通 Python 对象 / 队列；
    - 所有 Qt 对象的访问（包含 `QPixmap`、`QImage` 创建及 UI 刷新）严格限制在主线程（定时器 / signal-slot）。
  - 如未来再扩展新的后台任务，也沿用现有的「队列 + 定时器」模式，保持一致性。
